# diff-digest

Agents produce 2,000-line diffs. Reviewers skim them and approve, so review becomes
the bottleneck and the risky ten lines hide among the 1,990 safe ones. diff-digest
splits a diff into hunks, sorts every hunk by intent, scores its risk with the reasons
written out, and tells you which hunks to read first and which you can batch-approve.

## What it does

`scripts/digest.py` takes one of:

| Input | Meaning |
|---|---|
| *(nothing)* | merge-base of HEAD with `main` / `master` (or `origin/…`) compared with the working tree: committed and uncommitted tracked changes |
| `A..B`, `<rev>`, any `git diff` revision args | that range |
| `--staged` | the index |
| `--diff-file F` (`-` for stdin) | a saved unified diff |

Options: `--repo DIR`, `--json`.

**Groups** (each hunk lands in exactly one, checked in this order):

1. **generated**: lockfiles, `*.min.js`/`.css`, source maps, snapshots, `dist/`, `build/`, `vendor/`, protobuf output, and any hunk carrying an `@generated` / `DO NOT EDIT` / "Generated by Django" style marker (which covers auto-generated migrations).
2. **mechanical**: pure renames (git `-M`), import-only changes, whitespace or formatting only (the `-` and `+` sides are equal once whitespace is removed, so re-wrapped lines count), and identifier renames (each `-`/`+` line pair differs only by one consistent identifier swap).
3. **config/build**: `package.json`, `*.toml`, `*.yml`, `Dockerfile`, Makefiles, CI folders, `requirements*.txt` and similar.
4. **docs**: Markdown, reST, `docs/`, LICENSE, CHANGELOG.
5. **tests**: `tests/`, `test_*.py`, `*_test.go`, `*.test.ts`, `*.spec.js` and similar.
6. **deletions-only**: code hunks that only remove lines.
7. **core-logic**: everything else.

**Risk, 0 to 10 per hunk**, as the sum of the signals that fire:

| Signal | Points |
|---|---:|
| Touches auth, crypto, sessions, permissions, payments, SQL, eval/exec/subprocess (in markup and CSS only real secrets count) | 3 |
| Error handling removed (more `except`/`catch`/`rescue`/`finally`/`if err != nil` lines deleted than added) | 3 |
| Tests or assertions deleted (test hunks) | 3 |
| Conditionals changed (not counted for markup/CSS) | 2 |
| Public API signature changed or removed (`def`/`function`/`func`/`class`, names not starting with `_`) | 2 |
| No test change for that file in the same diff (code files only) | 1 |
| Large hunk: over 50 changed lines / over 150 | 1 / 2 |

Mechanical, generated and docs hunks score 0 (1 if a mechanical hunk is over 400 lines,
as a spot-check prompt).

**Output** (Markdown): a summary table (group, files, hunks, +/-, max risk), "Read these
first" (up to 10 hunks scoring 3 or more, highest first, as `file:line` with reasons; the
top 5 scoring hunks if none reach 3), every group as a collapsed `<details>` listing, and
"Safe to batch-approve" (mechanical, generated and docs hunks with risk 2 or less).
`--json` emits the same data with `"schema": "diff-digest/v1"`: `stats`, `groups`, `hunks`
(id, file, old_file, status, line, old_line, group, kind, additions, deletions, risk,
reasons, header), and `read_first` / `batch_approve` as lists of hunk ids.

**`/diff-digest:review [range]`** runs the digest, makes Claude open and read each
top-risk hunk in the real file (and its test), then write a short review: a verdict,
findings with `file:line` (bugs, removed error handling, security changes, untested
behaviour), missing tests, and one line per batch-approve group.

**Hook** (`PostToolUse`, matcher `Bash`): when `git push` or `gh pr create` succeeds, it runs
`git diff --shortstat` against the branch's base (merge-base with `origin/HEAD`,
`origin/main`, `origin/master`, `main` or `master`, else `@{upstream}`). Over 300 changed lines,
it adds context suggesting `/diff-digest:review`. Every git call has a 3 second timeout, and
any failure means no output.

## Install

```
/plugin marketplace add deepfieldstudios/deep-field-labs
/plugin install diff-digest@deep-field-labs
```

It can also be run directly: `python3 plugins/diff-digest/scripts/digest.py main..HEAD`.

## Config

- `DIFF_DIGEST_HOOK_LINES` (environment variable): the hook threshold, default 300.
- No state is written anywhere. The digest only runs read-only `git diff` / `merge-base`.

## Tests

```
cd plugins/diff-digest && python3 -m unittest discover -s tests
```

13 tests. A temporary git repo with a feature branch containing a rename, an import-only
change, a whitespace change, an identifier rename, a lockfile bump, a test change, a
risky auth change with a removed `try/except`, and an uncommitted README edit. They check
grouping, mechanical detection, risk ordering and reasons, the batch-approve list, deleted
test detection, the JSON schema, Markdown sections, the `--staged` / range / `--diff-file`
modes, parser edge cases (content lines that look like headers), and the push hook (big
diff, small diff, failed push, unrelated command, not a repo, bad JSON).

## Known limits

- Heuristic, line-based classification with no parsing. A hunk that is mostly an import
  change plus one real edit is core-logic; a "rename" that is actually two different
  variables that happen to swap consistently will look mechanical.
- Keyword risk is noisy in prose-heavy code (comments that mention "token" score too).
  Markup and CSS are deliberately treated leniently, so logic in inline `<script>` blocks
  is under-scored.
- Untracked files are not in the default diff (it is `git diff`, not `git add -N`). Stage
  them (`git add`) to include new files.
- "No matching test change" matches on file stem (`auth.py` and `test_auth.py`), not on
  real coverage.
- Binary files are listed with risk 0 and are never reviewed.
- The push hook measures the committed branch against its base. A push of the default
  branch itself falls back to `@{upstream}`, which is usually 0 just after a push.

## What a v1 would add

- Language-aware parsing (Python `ast`, tree-sitter where available) for real API-change and moved-code detection.
- Moved-block detection (`git diff --color-moved`) so cut-and-paste refactors count as mechanical.
- Coverage-aware "no test" signal from a coverage file when present.
- Per-repo risk config (`.claude/diff-digest.json`): extra sensitive paths, weights, ignore globs.
- Posting the digest as a PR comment via `gh`, gated behind an explicit command.
